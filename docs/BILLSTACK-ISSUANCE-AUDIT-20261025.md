# Billstack issuance and funding audit — 25 October 2026

The existing Railway gateway has `BILLSTACK_SECRET_KEY` and `BILLSTACK_PUBLICK_KEY` names, not `MASANAWA_BILLSTACK_SECRET_KEY`. The gateway now accepts the existing secret name as a fallback. This corrects configuration discovery; it does **not** qualify a live deposit. The gateway production domain currently reported by Railway is `masanawa-gateway-production-338f.up.railway.app`; its code webhook path is `POST /webhooks/billstack/gb`. Thus the URL to configure once provider qualification is complete is `https://masanawa-gateway-production-338f.up.railway.app/webhooks/billstack/gb`. Do not use a Railway project webhook, which reports deployments rather than customer payments.

Official [reserved-account creation](https://billstack.gitbook.io/api/reserved-account/create-account) specifies `POST https://api.billstack.co/v2/thirdparty/generateVirtualAccount/`, Bearer secret, reference, email, phone, firstName, lastName, one bank (`9PSB` in our adapter), and a single returned account. The [reserved-account overview](https://billstack.gitbook.io/api) says the number persists for a customer. The [webhook payload](https://billstack.gitbook.io/api/webhooks) identifies `PAYMENT_NOTIFICATION`/`PAYMENT_NOTIFIFICATION`, `RESERVED_ACCOUNT_TRANSACTION`, a transaction reference, original merchant reference, receiving account and amount. Billstack's [current website](https://billstack.co/) also advertises *one-time checkout accounts*, so the merchant must confirm that the provisioned product/key is the persistent reserved-account API before enabling issuance. Its published HMAC example agrees with `x-wiaxy-timestamp`/`x-wiaxy-signature-256` and SHA-256 of `timestamp.rawBody`; the repository test is simulated and cannot prove the live dashboard sends this contract.

## Missing end-to-end authority

- [ ] **First signup identity:** the phone-password path accepts a name but an optional email is only syntax-checked and discarded; it does not prove email ownership. The email-OTP path proves email but has no verified Nigerian phone. The name screen has a Skip placeholder and one freeform display name, not required first and last names. Billstack creation needs all four fields. Add required first/last/email and a verified phone binding, with an account-safe completion path for existing users. Do not use a typed email or password-only phone as verified identity.
- [ ] **Automatic issuance:** after verified signup identity commits, queue/reconcile one durable issuance per user, using the existing pending reference. Never send a second provider create after an unknown outcome. Confirm an official reference lookup/recovery API or manual operator reconciliation for pending references. The current `POST /v1/gb/wallet/virtual-account` is a manually triggered path and is gated off; viewing the balance card makes no financial write.
- [ ] **Provider product and applicant eligibility:** confirm the provisioned key permits persistent reserved 9PSB accounts, required KYC/no-BVN policy, sandbox/live mode, fees, limits, name/phone formats and account availability with Billstack. The source currently injects `billstackVerifiedApplicant`; production has no qualifying implementation.
- [ ] **Independent settlement and reversal:** obtain Billstack's documented lookup/final-status API and refund/reversal notification contract. The existing webhook validates a signed raw message and account/ref/kobo, then requires an independent `billstackSettlementVerifier`; production does not implement that port, so it cannot credit. Reversal debt/freeze journal exists internally but lacks a qualified event adapter. Test real provider duplicate, delayed, under/overpayment, reversal and lost webhook, with a real reserved account and small controlled deposit. Never treat a signed notification alone as final funds.
- [ ] **Operations:** configure the Billstack dashboard webhook to the URL above only after endpoint qualification and deployment; qualify rollout/migrations, historical callbacks, client cutoff, monitoring and reconciliation. Railway credentials are names only through the connected read tool; do not copy secret values into source or logs. `MASANAWA_NGN_FUNDING_VERIFIED` should remain off until all gates pass.

The compact Wallet/Send/Data card contains both balances and an account number when assigned. It never presents an unassigned number as a real bank account. No APK or Flutterwave fixed-IP hosting work is part of this audit.
