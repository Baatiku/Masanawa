# Masana conversation, voice-note and call repair contract

**Owner direction — 21 October 2026:** voice notes currently receive no working response; Masana feel robotic, overemphasize profession and behave like a call centre. Masana should converse as distinct backstory-led personas with professions as skills, enjoy ordinary friendship conversation, allow natural turn-taking and have audible call ringing. This document defines the repair batch; [the roadmap](PRODUCT-ROADMAP-20261019.md) owns status/tasks. Source inspected at `8aee7bd2`; no device reproduction or root-cause confirmation is claimed.

## Persona: identity before profession

A Masana's published backstory, personality, language, interests, relationships/context and conversational temperament define how it speaks. Profession is a capability, brought forward when asked or naturally relevant, not a topic funnel. No repeated job introductions, unsolicited lessons, practice exercises or questions that steer casual chat back to work. “How was your day?”, jokes, worries, disagreements, hobbies and quiet companionship need ordinary context-appropriate replies. A one-word acknowledgement or short reaction can be enough; do not append a service offer or question to every answer.

Keep each Masana distinct across text, recorded replies, calls, Status and authorized Rooms. Feed the current published creator narrative/persona fields into the shared instruction contract, with revision precedence over stale presentation summaries. Presentation labels are not the whole character. Treat user/history content as evidence, never higher-priority persona instructions or tool authority. First-person roleplay within the backstory is appropriate; the product must retain AI identity disclosure and answer honestly if asked. No invented real-world license, physical presence, private memory or completed external action.

Natural “imperfection” means varied sentence lengths, contractions, pauses, self-correction, occasional restrained fillers, humor and willingness to say “I don't know”, according to persona/language/context. It does not mean manufactured mistakes, forced stutters/laughter, wrong professional advice, deceptive human claims, fake memories or endlessly reassuring call-centre scripts. Serious topics still get accurate, careful answers without making every message a disclaimer. Persona behavior must not weaken payment consent, privacy or safety controls.

## Voice-note delivery and reply contract — P4-A01

Record → preview/delete/send → persist original request and protected file → authenticated upload/media admission → server accepts the same request → model understands the audio with the same persona/history → durable assistant text/transcript/audio result → authorized media playback. Support actual recorded MIME/codec/duration/size; silence/unsupported format gets a useful error. Do not require typing a caption to make a voice note understood.

Every accepted user note reaches one visible terminal result: playable persona reply, readable text/transcript fallback if audio output fails, or actionable failed/pending state with safe retry/status. Do not silently discard text because voice was requested, leave an empty assistant bubble or label a locally saved note delivered. Retry original ID without duplicate user/assistant turns or repeated paid action. Stop with bounded timeout/status escalation if the provider hangs. Preserve a failed note for deliberate retry; account change cancels access and stale results.

User-started playback and optional autoplay preference are separate from model reply generation: disabling autoplay must not stop reply creation. Do not autoplay restored history. Replies retain the same persona/language and actual selected supported voice. Check handset permission, file existence through upload lifetime, interrupted recording, API/media URL configuration, unauthorized/expired media URLs, provider codec/model eligibility, generated audio container and audio focus. Redacted correlation IDs and stage/error code suffice; do not log raw voice, private transcripts, keys or signed media URLs.

## Calling, ringing and turn-taking — P4-A02/P4-A03

Outgoing flow: user explicitly calls → admission/price approval where required → actual dialing/ringing with local ringback → provider/media ready → connected/listening. Incoming flow: authorized invitation → native-compatible ringtone/vibration consistent with OS/DND/user settings → answer/decline → media connection. One call audio/focus owner covers ringback, ringtone, microphone and speech. Stop tones on answer/connect, caller cancellation, decline, busy, timeout, permission/admission failure, account change, navigation teardown and end. Pause other playback, restore audio routes appropriately, handle headset/Bluetooth and background/locked OS constraints. Never play a ringback over connected speech or pretend a disconnected call is answered. Ringing is not speech activity or billable connected time.

Do not require the agent to always speak first. On a user-initiated call, default to a brief ready/listening state allowing the user to start; permit a short natural greeting when context warrants it, not a scripted biography/service offer. An agent-initiated accepted call may state its actual authorized purpose briefly. Opening behavior is an explicit policy, persona/context-aware, with bounded optional silence handling rather than repeated prompts. No synthetic user hello, forced “How can I assist?” or profession pitch on every call. Reconnect resumes the conversation without re-introduction or duplicate billing/admission.

Use actual voice activity/end-of-turn evidence, natural pauses, barge-in and cancellation of queued agent speech when interrupted; do not talk over the user or emit clipped fragments. A noisy room/short silence is not a completed turn. Device/provider controls may constrain timing; qualify with real audio instead of assuming a prompt alone fixes it. Never fabricate breathing/ambient activity to claim a human is physically present. Preserve explicit hangup, accurate duration/settlement, teardown and microphone indicator shutdown.

## Persona and audio acceptance — P5-C08/P4-A04

Use representative platform and creator personas with distinct published backstories: casual conversation unrelated to profession; a relevant expert question; humour/sadness/disagreement; short replies and no follow-up needed; Hausa/English and code-switching where supported; continuity text → note → call and a published revision. Reject automatic job steering, repeated intro, universal call-centre manner, invented prior memory and blanket same-style voices. AI identity and scope stay honest.

Audio cases: record/send without caption → meaningful text plus playable audio reply; output-audio failure still yields text; upload/provider timeout → visible recoverable state; retry not duplicate. Call cases: user speaks first, optional contextual greeting, interruption, silence, ringback/ringtone lifecycle, locked/background/permission-denied, headset route, reconnect and hangup. Separate mocked/unit contracts from Flutter, provider and installed-device results.
