Only verified whole-GB bundles costing at least 1,000 MB remain eligible.

New funding composition must fail closed until contract qualification; legacy signed historical callbacks/receipts are preserved. Existing MB and prior direct-MB deposits are never repriced, recredited NGN or silently reversed by the new ledger. Duplicate event identity must be checked across both journals. A provider-reversed NGN deposit records a compensating immutable entry; already exchanged/spent funds require debt/freeze and operator reconciliation rather than deleting money history.

## Source delivery and qualification boundary

The forward migration is `0205_ngn_funding_wallet.sql` (0204 left for the existing call-runtime worktree). It creates isolated cash accounts, immutable deposit/exchange/reversal entries and provider event identities. Deposits and retained historical MB settlement share an event mutex and cross-check journals. Existing balances/carry/receipts are never backfilled. An NGN exchange is distinctly typed `ngn_exchange` in the existing MB operations ledger and atomically linked to its cash debit. Readback waits behind the original exchange lock; the database checks quote expiry inside that lock so expired, undispatched work cannot later spend after definitive recovery.

The new quantity version `ngn-quantity-v1` implements the earlier proposed ladder through 2 TB, custom 1–2,000 whole GB, exact kobo and actor-bound HMAC review with a separate domain from Send. New prices remain disabled unless `MASANAWA_NGN_EXCHANGE_ENABLED=true` after cost/margin/limits qualification. Public historical preview routes remain non-mutating compatibility; the mobile Add data chooser now uses `/v1/gb/wallet/exchange/packages` and never promises deposit-derived MB.

The mobile saves its original signed review in account-scoped secure storage before POST. Lost replies lock a new purchase across screen/app reopening. It checks the original receipt; only an explicit retry can replay that same review/key. Server-expired, definitively unspent reviews can be cleared; an unknown network result never becomes success. Account/login epochs reject late responses. A separate `/wallet/fund` route handles funding instructions, preserves the package screen behind it and never automatically buys MB. Read-only cards never allocate accounts.

Funding remains **BLOCKED for production**. `MASANAWA_NGN_FUNDING_VERIFIED=true` alone is insufficient: composition also requires a qualified independent `billstackSettlementVerifier` checking the provider's final transaction, exact amount and receiving account. Account creation separately needs `billstackVerifiedApplicant`; raw profile name/phone fields are not eligibility proof. No production implementation of these qualified provider ports is invented here. Existing assigned-account readback is retained, and funding instructions are disabled while verification is unavailable. Reversal repository methods are trusted internal ports only; no guessed provider reversal payload or public manual cash credit endpoint exists. Cash spent before reversal creates debt and freezes both cash and MB; later funding pays debt first without automatically lifting the reconciliation hold.

Data shows only Daily (verified 1 day), Weekly (7 days) and Monthly (28–31 days). Other durations are excluded, never relabeled or deleted from provider history. At normal phone size the cards use three columns, then two/one for narrow/large text. Approved network-logo assets, real handset visuals, official provider contracts, limits/cost verification, deployment/migration and real settlement are still separate acceptance gates.


The Billstack HTTP credit port is now explicitly NGN-only (`creditedKobo`); it no longer accepts a deposit-to-MB pricing callback. Historical preview endpoints are labeled `historical_reference_only`/`automaticDepositConversion:false` and link the current package path. Preserve their old rate math strictly for historical compatibility. A production cutover must also qualify minimum supported client version, backup/migration, delayed old callbacks and old-client funding instructions before enabling any deposits. No minimum-client rollout or infrastructure setting has been changed here.
