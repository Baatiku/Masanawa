## Universal presentation and state rules

Actors: phone/email-authenticated human, signed-out/recovering human, authorized platform editor/admin, platform Masana, provider callback (server only). Root navigation is a persistent accessible 5-item bottom bar: **Home (the renamed existing Status feed) first/leftmost and selected by default**, Chats second, followed by Wallet, Calls and Data. No duplicate/new Home feed is created. Existing `?tab=status` and `/status/:postId` deep links remain compatible. Each tab retains bounded scroll/selection for the same active account and destroys private state on user switch. Supported deep links route to account-bound content; retired routes only redirect to appropriate canonical tab. Protected content never flashes during session restore.

Owner signup update, 25 October (current source baseline, to be expanded by Batch F): new mobile sign-in uses email OTP only. First signup asks for first name, last name and a Nigerian-format contact phone after OTP proof, with no Skip. The contact phone is kept separately from the authenticated email and must never become a phone sign-in credential. Returning email users keep their existing session flow. Data redemption prefills that contact phone for the active account, permits an editable different recipient, and clears prior recipient/network/quote on account switch. Invalid/missing contact leaves a blank input, never a guessed number. Back from first-signup details returns to the OTP entry; loading/error/expired-code states retain the verified email and editable details. Narrow/large-text/RTL forms scroll without clipping.

First-signup completion repair: a successful `/auth/verify` with `isNewUser: true` is fully authenticated after the required names/contact are accepted. The home gate must render the five tabs for every `SessionSignedIn`, including the first session and a restored persisted first-session token. `isNewUser` only triggers the one-time Billstack assignment attempt; it never blanks or delays the shell. While the verify/assignment request is pending, the name form remains visible; assignment failure must not undo the signed-in transition. Signed-out/restoring states keep their existing protected-content gates.

If the automatic account request was interrupted before reaching the Gateway, Fund NGN displays **Get funding account** when assignment is available. An assigned account can be read while deposit credit remains unverified. A pending account never triggers a second provider create; users see its pending state and a Check status action. The Fund screen hides transfer instructions while funding is disabled, even if an account number was allocated.

Design: white/neutral background, restrained green emphasis, compact 16px card spacing, 48dp minimum actionable touch size, no perpetual backdrop blur, semantic labels, keyboard/screen-reader navigation, directionally safe RTL icons, 320dp/200%-text wrapping, reduced-motion respect. Amounts: integer MB stored, locale-grouped exact MB always shown under trimmed decimal GB (e.g. 10,375 MB = 10.375 GB). Server UTC timestamps rendered in local time; no negative spendable or speculative "success".

Every async screen: (1) initial loading with non-private skeleton, (2) authorized success, (3) empty with appropriate next action, (4) retriable network/provider error preserving safe inputs, (5) offline no implicit paid action, (6) permission denied with fallbacks, (7) expired credentials/session refreshing safe GET reads only, and (8) account switch cancel/blank stale rows and stop in-flight writes. All writes have disabled double-submit and original-receipt resumption.
