6. Safety: no secrets, PII or real keys in source, logs, tests or PRs. No unqualified production issuance, paid side effects, destructive migrations or irreversible deletion. Preserve encrypted backups, telemetry, account deletion and rollback obligations.
7. Before coding: inspect fresh main, open PRs/issues/claims and affected code/tests. Own exact paths; shared router/financial ledger/migration registry/deployment one integrator. Never overwrite another contributor's head, force push a shared branch, or delete unfinished source.
8. For UI work: specify page tree, nav/back/deep-link, controls and all loading/empty/error/offline/permission/account-switch states from SCREEN-JOURNEYS first. Prefer minimal working flows, reusable Flutter components, accessibility, small screens, RTL, low data.
9. For delivery: source + test in scoped PR; run reachable TS/Vitest/PostgreSQL/Flutter/Android checks, container fallback where runner unavailable, honest NOT_RUN labels. Merge compatible completed development promptly, with actual security/test failure repaired. Owner does final acceptance; do not equate integration with VERIFIED_E2E or DEPLOYED_VERIFIED.
10. Source-of-truth order: executable behavior at exact SHA → roadmap/owner decisions → current technical/API/security/financial contracts → actual PR evidence. No historical branch, Git commit or external document may override current owner authorization.
11. Keep approved implementation practical: no duplicate backend providers/ledgers, unnecessary microservices, expensive dormant services, forced custom voice onboarding, synthetic fund claims or undisclosed hidden fees.
